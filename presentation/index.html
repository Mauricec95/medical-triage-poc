Pain Points

  • Critical info frequently missing — injection status, creatinine, prescriber contact
  • Manual triage takes ~5 min per request
  • Back-and-forth phone calls to chase missing data
  • Risk of errors in routing urgent vs. routine exams

What the Secretariat Must Do

6 steps, repeated hundreds of times per day — manually

1. Triage

Classify by exam type, urgency, and modality (Scanner, IRM, Doppler, Echo, Radio)

2. Extract

Pull structured info: patient identity, prescriber, exam details, clinical indication, attachments

3. Detect gaps

Flag missing or ambiguous fields — e.g., "coroscanner" without injection info, no creatinine result

4. Route

Send to right contact: prescriber service, patient, radiologist for validation, or admissions

5. Acknowledge

Send a secure, professional acknowledgement in French (vouvoiement) to reduce repeat calls

6. Prepare

Format the request for scheduling in the RIS (Radiology Information System)

Data Model — MedicalRequest

Pydantic as the single source of truth

# Core structured request (10 fields) class MedicalRequest(BaseModel): patient: PatientInfo # name, dob, sex, phone, email prescriber: PrescriberInfo # name, specialty, hospital exam: ExamInfo # modality, region, injection clinical_indication: str required_attachments: list[Attachment] missing_fields: list[MissingField] routing: Routing # next_action + rationale ack_message_fr: str # Ready-to-send French ack confidence: float # 0.1 – 0.95 source: SourceInfo # channel, raw_text # Enums enforce strict domain vocabulary Modality: scanner | IRM | doppler | echo | radio Urgency: routine | prioritaire | urgent NextAction: contact_prescriber | contact_patient | await_radiologist | schedule | reject

Design Decisions

  • Pydantic validation — catches malformed data at the boundary, not at runtime
  • Optional fields everywhere — real-world medical docs are always incomplete
  • MissingField tracks the field_path, reason, AND a suggested question in French
  • Confidence score — computed from completeness (0.1-0.95), never reaches 1.0
  • DB model stores JSON blob — flexible schema evolution without migrations

MissingField Example

field_path: "exam.with_injection" reason: "Injection non précisée" suggested_question_fr: "L'examen est-il demandé avec ou sans injection de produit de contraste ?"

Dual Extraction Strategy

LLM for accuracy, regex for reliability — swap freely

LLM Path (GPT-4o)

  • French system prompt in a dedicated Markdown file — easy to iterate
  • JSON structured output via response_format
  • Handles ambiguity, abbreviations, and messy handwriting transcripts
  • Swappable: thin wrapper lets you switch to Mistral, Claude, or any provider
High accuracy Requires API key ~2s latency

Regex Path (Fallback)

  • 30+ French regex patterns for patient names, DOB, phone, email, prescriber, modality
  • Keyword mapping: "coroscanner" → scanner, "remnance" → IRM, "rx" → radio
  • Zero dependencies, runs offline, deterministic
  • Used for all 180 unit tests — no API key needed for CI
Zero cost Deterministic Offline

Rule-Based Validator

13 business rules applied on top of LLM output — the AI doesn't get the final say

#RuleAction
1-3Patient name, DOB, contactFlag if missing
4-5Prescriber name + contactFlag if missing
6-7Modality + regionFlag if missing
8Scanner/IRM → injection statusRequire explicit yes/no
9Injection=true → creatinineRequire lab result
10Ordonnance attachedFlag if not found
11Clinical indicationFlag if missing
12Age < 10 → pediatric flagCoordination required
13Urgency-aware routingUrgent → radiologist

Why rules on top of LLM?

  • LLMs hallucinate — rules catch domain violations
  • Regulatory requirements are deterministic, not probabilistic
  • Rules are auditable and testable (180 tests)
  • Easy to add new rules without retraining

Smart Routing Priority

When multiple fields are missing, routing follows this priority:

  1. Prescriber info missing → contact prescriber
  2. Clinical info missing → contact prescriber
  3. Patient info missing → contact patient
  4. Attachments missing → contact prescriber
  5. Complete + urgent → radiologist validation
  6. Complete + routine → schedule directly

The UI — French-First Design

Inbox → Detail → Edit → Send — designed for secretariat workflows

Inbox View

  • Table with 7 columns: Patient, Modalité, Urgence, Statut, Manquants, Source, Date
  • Color-coded status chips: Complet Incomplet À valider Routé
  • Urgency labels: URGENT / Prioritaire / Routine

Detail View (Two-Column)

  • Left: Original raw text / PDF preview
  • Right: Editable structured form — all fields modifiable
  • Missing fields section with red cards and French questions
  • Confidence bar (0-95%)
  • Ack message textarea — editable before sending
  • "Envoyer (mock)" → status changes to Routé

Key UI Decisions

  • All French labels — UI uses vouvoiement and hospital register
  • Editable before send — human-in-the-loop, AI suggests but human decides
  • Missing fields show suggested questions — secretary can copy-paste into email
  • Confidence score visible — transparency about AI uncertainty
  • Status tracking — clear workflow: Incomplet → À valider → Complet → Routé
